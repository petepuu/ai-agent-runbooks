# Employee Self-Service Agent (GHCP)

## Scenario Overview

| Attribute | Value |
|---|---|
| Scenario type | Employee experience: one HR + IT front door |
| Build | Custom Microsoft Copilot Studio agent powered by the GitHub Copilot harness |
| Components | Instructions, connected knowledge, four reusable Agent Skills, optional live read-only tools |
| Channels | Microsoft 365 Copilot and Microsoft Teams |
| Complexity | Intermediate; content, identity, and audience readiness dominate delivery |
| Status | Implementation guide and skill files; target-tenant validation required |
| Documentation reviewed | September 15, 2026 |

This is a separate adaptation of [Employee Self-Service Agent](../Employee-Self-Service-Agent/1.Overview.md). It preserves the employee front door, HR/IT knowledge curation, catalog routing, optional own-request status, deflection baseline, and representative pilot. The original scenario remains unchanged.

**GHCP means the runtime harness inside Copilot Studio.** It is not GitHub Copilot coding agent, a GitHub Actions workflow, or GitHub Copilot Chat used to edit ESS components in VS Code. Publishing this folder to GitHub does not install an agent or connect enterprise systems.

## Problem and Intended Outcomes

Employees bounce between HR portals, IT service catalogs, and SharePoint to answer routine questions or find the right form. The goal is one governed front door that answers from approved evidence, identifies the applicable policy, and routes actions to the correct system.

Measure reduced repetitive HR/IT inquiries, faster time to answer, correct request routing, and better employee adoption. Do not count a plausible answer, a portal link, or an abandoned conversation as proven ticket deflection. Preserve the original scenario's readiness-first approach: a stronger runtime does not fix contradictory policies or missing source permissions.

## Microsoft ESS Template vs This Custom Build

The original scenario offers the Microsoft ESS template or a custom equivalent. Microsoft documents ESS HR and IT starters with topics, connectors, flows, and integrations. **This GHCP scenario is a custom alternative, not a conversion of those starters or a promise of feature parity.**

Microsoft explicitly says standard-harness and GHCP agents cannot be transferred between harnesses. The reviewed documentation does not establish an ESS-template or Agent Builder conversion route to GHCP. Reuse approved sources and integration requirements; recreate the agent's configuration and prove the selected scope.

ESS program access, accelerator support, and template-specific connector entitlements are not GHCP eligibility requirements or licensing benefits. Likewise, the ESS Developer Kit's use of GitHub Copilot Chat does not establish that an installed ESS agent uses the GHCP harness.

## Standard / Original Build vs GHCP

| Area | Original options | GHCP implementation |
|---|---|---|
| Agent choice | Microsoft ESS template, Agent Builder, or custom Copilot Studio | A new custom GHCP agent; retain the template/standard option if it better meets requirements |
| Authoring | Template topics/flows, declarative instructions, or standard topics and configurable orchestration | Build surface with instructions, knowledge, tools, skills, model, and memory; enhanced orchestration |
| Reusable behavior | One broad instruction block or topic/flow components | Four focused Markdown skills for HR policy, IT guidance, catalog routing, and optional own-request status |
| Skills meaning | Existing topics, flows, and older Bot Framework skills are different components | Portable `SKILL.md` instructions with YAML metadata; optional supporting resources |
| Source integration | HRIS, ServiceNow, and SharePoint routes vary by chosen template/custom build | Verify each source in the GHCP picker; do not assume template connectors transfer |
| Catalog | Find the item or request form | Retrieve a verified item URL; catalog knowledge is not request submission or request history |
| Live status | Available only where the selected build/integration supports it | Optional authorized read-only tools, separate from indexed knowledge |
| Context | Country/location scoping, sometimes Entra attributes | Separate data authorization from policy applicability; no location-by-prompt access control |
| Determinism | Topics and flows can explicitly enforce paths | Skills guide model behavior; backend/tool logic must enforce identity, ownership, and write restrictions |
| Memory | No persistent-memory design in the original | Off by default for HR/privacy minimization; not a source of live request state |
| Evaluation | Baseline categories, boundary tests, three repeated runs, pilot | Retain these and add skill-selection, live-tool authorization, error, and pagination cases through Preview/Evaluate/Monitor |
| Licensing | Depends on template, Agent Builder, or standard route | GHCP consumes Copilot Credits separately from Microsoft 365 Copilot user licensing, including build/test/evaluation |

Standard Copilot Studio can use generative orchestration; the comparison does not imply that all standard agents are fixed scripts. Skill descriptions are not deterministic routing rules, and importing a skill installs neither knowledge nor tools.

## Deployment Tiers

| Tier | Included behavior | Required evidence |
|---|---|---|
| Baseline: grounded self-service | HR policy, IT how-to, exact catalog/form links where available; status requests get an honest portal fallback | Correct sources, permissions, applicability, citations, language and audience access |
| Optional: own request status | Live read-only view of the employee's permitted IT/catalog requests | Verified tool binding, caller identity and backend ownership enforcement, error behavior, pagination, source parity |

All four supplied skills can be installed in the baseline. The status skill explicitly reports when the optional integration is unavailable; it never invents results. Transactional HR writes, live pay/leave/benefit data, personal HR cases, ticket creation/updates, and email sending are out of scope in both tiers.

## Source and Integration Readiness

| Source | Position for this GHCP build |
|---|---|
| SharePoint | Explicit GHCP knowledge source; select approved HR/IT sites and test permissions |
| ServiceNow Knowledge | Explicit GHCP source; configure the Microsoft Copilot Connector and validate user criteria, HR-specific permissions, and indexing |
| ServiceNow Catalog | Microsoft provides an indexed Catalog connector; verify its configured connection is available and functional in the target GHCP environment before promising exact-item routing |
| Workday / SAP SuccessFactors | ESS documents integrations, but the reviewed GHCP source inventory does not name them as knowledge sources; validate the actual connector/tool route rather than assuming template parity or claiming no connector exists |
| Own request status | Requires a live authorized tool; knowledge or catalog indexing cannot establish current personal request state |

If the HRIS route is not ready, use an explicitly reduced, HR-approved SharePoint + ITSM pilot. Do not silently replace a live personal-data request with a generic knowledge answer.

## Qualification and Delivery Ownership

Before committing to scope, record the GHCP environment/cloud, target licensed and Copilot Chat populations, frontline access, languages/countries, HRIS and ITSM integration paths, content owners, HR sponsor, IT support owner, approved portal/contact routes, and cost owner.

Capture the **top 25 question categories and volumes before deployment**. Audit duplicate policies, source authority, applicability, effective dates, permission mappings, and actual text/table extraction. Pilot representative countries/business units and frontline users where in scope, not only makers and administrators.

The proposed quality target remains at least **80% correct and consistent baseline answers**, plus a separate zero-tolerance gate for unauthorized disclosure or unintended writes. These are scenario acceptance targets, not platform guarantees.
