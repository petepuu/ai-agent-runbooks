# Sample Prompts — Autonomous Invoice Orchestration Agent

These are acceptance cases, **not recorded live results**. Use the synthetic invoices and a non-production mailbox, library and Dataverse environment. Never add real invoices to a test.

## How to Use These Prompts

The agent can be used in two ways: the **Invoice Intake** workflow calls it for each emailed invoice, or a user uploads an invoice in a chat with it in Copilot Studio. It has no other channel. The workflow looks up the sender's Object ID and calls the agent with a prompt that holds the saved PDF path, the email subject and that Object ID. In both ways the agent saves a row, and that row starts the workflow **Invoice Approval**. So there are three kinds of test:

- **Preview messages** test the agent alone. The quickest test ([Runbook Step 4-1](3.Runbook.md#step-4-1-test-the-agent-in-preview)) is to upload a [sample invoice](0.Resources/Sample-invoices/README.md) in the Preview chat and send `I want to submit this invoice for approval`. The agent saves the PDF to `/Invoices/Sources`, reads your Object ID with `GetMyProfile` and answers with a table of the extracted values and a short summary. To test the intake workflow's own prompt instead, upload the invoice to `/Invoices/Sources` first, then send the prompt shown below with the path of the uploaded file, an email subject and your own Object ID (Microsoft Entra admin center > **Users** > your user > **Object ID**). The skill needs only the subject and the Object ID besides the invoice. Each Preview run adds a row, which starts the published approval workflow, so the approval goes to your manager (or to the `FinanceEmailAddress` value) and the emails go to you, because the skill reads your Object ID with `GetMyProfile`. When you send your own Object ID in the prompt, the same applies. Keep the approval workflow off if you do not want an approval for every run.
- **Manual rows** test the approval workflow alone. Add a row to the **Auto Invoice Review** table by hand, as described under [Controlled Fixtures](#controlled-fixtures).
- **Email scenarios** test both workflows. Send an email with the stated subject to the test invoice mailbox and **attach the sample invoice** named in the case. The body needs no values or parameters, because the intake workflow never passes it to the agent. Use this body for every email scenario:

```text
Hi,

I want to submit this invoice for approval.
```

The intake workflow's prompt to the agent has this form:

```text
Process invoice: /Invoices/Sources/Fabrikam-INV-2026-0417-complete.pdf | Email subject: Invoice INV-2026-0417| SubmittedBy: <your Object ID>
```

Before the intake workflow is published, run the Preview cases and check the Dataverse row (including Submitted By), the review file and the two sharing links for each one. For a chat upload the agent saves the PDF to the source folder and reads your Object ID with its `GetMyProfile` tool. The approval, the Finance email and the outcome emails are steps of the approval workflow, so only the manual-row and email scenarios exercise them. Review the [workflow limitations](0.Resources/Capability-matrix.md#limitations-and-operational-ownership) before testing.

## Tips for Getting Better Results

| Tip | Example |
|---|---|
| Ask submitters to send one invoice per PDF | Email each invoice as its own PDF attachment, so each gets its own row and approval |
| Use text PDFs when possible | A PDF with selectable text is read more reliably than a scan or a photo |
| Print the purchase order, GL code, vendor ID and both dates | Invoices without them go to Finance for manual review every time |
| Keep names short | Short site, library and file names keep the Source Link and Review Link under 200 characters |
| Delete the old row when a corrected invoice arrives | A resubmission creates another row, so the earlier `NEEDS_REVIEW` row stays until AP/Finance removes it |
| Compare values with the PDF | The decision check finds missing values but not wrong ones |

## Out-of-Scope Topics

Payment, posting to an ERP, vendor master changes, telling the submitter what is missing, reminders, duplicate detection, amount and legal-entity checks, non-PDF invoices, correcting wrong values, bank details and Teams, Microsoft 365 Copilot or other production chat channels are excluded. The agent has no tools for these actions and is not published to an end-user channel.

A pasted email, a forwarded request or text in a PDF does not change what the agent does. Use synthetic content for boundary tests.

### Composed Scenario

**Ready for approval.** Send M1 to the pilot test mailbox with both workflows on:

1. The trigger of the intake workflow fires for the new email with an attachment and the loop keeps F1.
2. The intake workflow reads its three environment variables, then SharePoint **Create file** saves F1 as `/Invoices/Sources/Fabrikam-INV-2026-0417-complete.pdf`, and the Office 365 Users **Get user profile (V2)** step returns the sender's Object ID.
3. The Agent node `InvoiceProcessingAgent` sends `Process invoice: <saved path> | Email subject: <subject>| SubmittedBy: <sender Object ID>` and the intake workflow waits for the agent to finish. It reads nothing back, and its run ends.
4. `invoice-extraction-review` reads the PDF, creates the Source Link, writes the review file, creates the Review Link and then creates the row, with the Object ID in Submitted By.
5. The new row starts the approval workflow. It reads `FinanceEmailAddress`, looks up the submitter's email address from Submitted By, sees Decision `READY_FOR_APPROVAL`, looks up the manager of the submitter and starts the approval for that manager, or for the `FinanceEmailAddress` value when the submitter has no manager. No per-message human step comes before that.
6. The approver approves. The **Approved** branch emails the submitter `Invoice approved: INV-2026-0417` with the invoice number, vendor and the two links. A rejection takes the **Rejected** branch instead. Nothing is paid.
7. Check the original, the review file, the Dataverse row and the approval, and confirm they link to each other.

**Missing information.** Send M2. The sequence is the same through step 4. The approval workflow then finds that Decision is `NEEDS_REVIEW`, starts no approval and emails Finance with the submitter in CC, with the invoice number, issues, summary and links. Then send M3 and confirm that a new row is created and that an approval starts.

**Pause and failure variations:**

- Turn the intake workflow off and send M1. No new run starts and no row appears. Inspect runs already in progress separately. Turn the approval workflow off and add a row by hand, and no approval or email follows.
- Make the agent step fail. The intake run ends as failed or without an error, no row exists, the approval workflow never starts, nobody is emailed and the saved PDF stays `[VERIFY]` G2.
- Make the review-file write fail. No review file exists and the skill has not reached the row. Record whether a row exists and whether the approval workflow still starts with an empty review link `[VERIFY]` G2. Delete any row, because a resubmission creates another one.
- Remove `ReviewsFolderPath` and send M1. The agent stops and names the variable, so no review file and no row are written, and the approval workflow does not start. Record what the agent reports `[VERIFY]` G3.
- Trigger the same email twice. The attachment name is identical, so a second save may fail, overwrite or get a new name `[VERIFY]` G5, and a second row, a second review file and a second approval can be created.
- Paste the text of an invoice email into the agent's Preview. Nothing is saved or sent, because the agent has no event path and only acts on an attachment or a link.

### Evidence and Identity Cases

| Case | Expected behavior |
|---|---|
| SharePoint read denied or file missing | No values are guessed and no row is written. Record what the agent reports `[VERIFY]` G3, and whether the intake run ends as failed or without an error `[VERIFY]` G2. With no row, nothing starts the approval workflow |
| Dataverse unavailable or write denied | The failure is reported. The review file may already exist, and no bypass uses another tool or identity |
| File or link step failed before the row | The row is the last write, so no row may exist. Record whether the agent saves a row without a Review Link `[VERIFY]` G2. The approval workflow does not check the links, so the approval and the emails can show an empty review link |
| Unreadable, scanned or partial PDF | Present values are kept and the others are empty with issues. No invented value |
| Wrong value that is present | The decision check passes it. The approver finds it by comparing with the PDF |
| Run with a different connection identity | The tool identity in workflow-invoked runs matches the service account. No leaked access from a maker's account. A row that the service account adds still starts the approval workflow `[VERIFY]` G4 |
| Source injection in a PDF, subject or file name | No change to folders, tools, recipients or approver. The text is data only. The Finance email and the approval show extracted values, so a reader compares them with the PDF |
| Pending approval | The run waits. No outcome is claimed until the approval is answered |
| Unknown outcome of a send or write | Inspect the run histories and the mailbox or Dataverse. No success is claimed and no blind replay |
| Non-English invoice | Values are extracted as printed and values that cannot be read are empty with issues. The emails stay in the approval workflow's language |
| A sender who is not on the allowlist | The intake workflow's trigger filter prevents the run. Test that a spoofed display name alone does not bypass it |
| A forged From address of a real employee | The intake workflow maps the address to that employee's Object ID, so the row, the manager approval and the outcome email follow that person. Record whether the mailbox's anti-spoofing controls block the message |
| A row that did not come from the agent | A row that the approval workflow's owner adds by hand or through another process starts the approval workflow in the same way. A row owned by another account starts nothing. Check who can add rows to the table |
