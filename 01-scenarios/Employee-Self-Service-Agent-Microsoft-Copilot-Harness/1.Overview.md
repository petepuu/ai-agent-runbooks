# Employee Self-Service Agent with Microsoft Copilot Harness - Overview

> **Scenario Type**: Employee Experience (HR + IT self-service)  
> **Agent Type**: Microsoft Copilot Studio agent, Microsoft Copilot Harness  
> **Primary Tools**: SharePoint and ServiceNow knowledge; proposed delegated ServiceNow and Workday tools  
> **Status**: Authoring blueprint and seven starter runtime skill definitions; integrations not implemented or deployed.\
> **Source**: [Employee-Self-Service-Agent](../Employee-Self-Service-Agent/1.Overview.md), local revision `a776697d6c072ec6d4cf8b09ba7670bd11a3e73c`.  
> **Authored**: 2026-10-28. The original scenario remains unchanged.

**Starter scope updated:** 2026-11-11 using seven supplied ServiceNow and Workday skill definitions. The earlier 28-skill set is replaced, not required for initial delivery.

## Scenario overview

Give employees one authenticated HR and IT front door: answer policy and troubleshooting questions from approved **SharePoint and ServiceNow knowledge**, then, when separately enabled, work with the employee's own **ServiceNow HR cases, ServiceNow IT incidents and Workday information**.

This is a standalone sibling design. The source describes several build options, not a delivered topic-based agent. This variant uses global instructions for knowledge/navigation and seven focused live-operation skills for the **Microsoft Copilot Harness inside Copilot Studio**, not Copilot CLI or GitHub coding agents.

**Implementation boundary:** This repository supplies the procedures and contracts, **not executable connectors, MCP servers or workflows**. Uploading skills does not create integrations or grant access. Live capabilities stay OFF until a supported Microsoft Copilot Harness integration is delivered and validated.

## Users and outcomes

| Persona | Need | Measurable outcome |
|---|---|---|
| Employee | Find the applicable HR policy or IT fix without portal hopping | Time to a correct cited answer, compared with a pre-pilot baseline |
| Employee with enabled transactions | Read own requests and HR information; make a specifically confirmed change | Authorized read accuracy and verified completion; no cross-user disclosure or duplicate writes |
| HR Operations | Consistent guidance and own-case visibility | Deflection for the top 25 question categories; source-owner review of failures |
| IT service desk | Useful incident descriptions and transparent status | Confirmed incident creation, description fidelity and fewer status-chasing contacts |
| Delivery, identity and system owners | Independently enable capabilities without widening access | Signed capability manifest and positive/negative authorization evidence |

These are measures to collect, not achieved results. Establish baselines before the pilot.

## Capabilities and scope

| Capability | Evidence / system | Boundary |
|---|---|---|
| Policy and IT answers | Approved SharePoint libraries and ServiceNow KB articles | Source-grounded, cited, country/effective-date aware; no personal entitlement calculation |
| Request navigation | Approved links retrieved from those sources | Link only; navigation does not submit a request or order a catalog item |
| ServiceNow HRSD | List own HR cases | Employee-visible Number, State, HR Service and Short Description; no case creation/update |
| ServiceNow ITSM | Create an incident and list own active incidents | Own caller; severity and short description; no catalog orders, updates or attachments |
| Workday reads | Own Cost Center and approved employee information, including requested absence balances | Exact Cost Center type; core profile fields only, with home contacts/balances fetched only when requested |
| Workday home phone | Update an existing own home phone through one business-process event | Preserve untouched fields; explicit staging/submission approval; no add/delete or work-phone changes |
| Workday time off | Submit standard Time Off / Absence Table requests | Validate eligible type, dates, daily quantities/units, balance and overlaps; confirmation; submission is not approval |

The [matrix](0.Resources/Capability-matrix.md) lists the seven skills, dependencies and states. Knowledge answers and navigation need no separate skill; enable configured knowledge **after** source validation. Every live skill is optional and OFF initially; a knowledge-only pilot must be labeled as reduced scope, not a full implementation.

**Excluded from the starter scope:** SAP SuccessFactors; Leave of Absence; time-off approval/cancellation; HR-case creation/updates and incident updates/attachments; Workday email updates; new phone creation or work-phone changes; specialist reads such as compensation, national IDs, passports, visas and emergency contacts; payroll calculations and payslips; benefits enrollment; compensation changes; manager/on-behalf-of access; bulk export; employee profiling; autonomous triggers; mail sending; provisioning; catalog checkout; legal, tax or medical advice. Grievances, termination, discrimination and compensation disputes receive only an approved human contact route; do not collect their narrative into ordinary tickets.

## Compatibility and deliberate changes

| Source behavior | Microsoft Copilot Harness behavior | Disposition |
|---|---|---|
| HR + IT front door, curated content, representative pilot | Same business purpose with SharePoint and ServiceNow KB knowledge | Retained |
| Multiple build options | One new Microsoft Copilot Harness agent; source choices remain useful | Standalone implementation |
| Portal links for requests | Navigation remains available independently of writes | Retained |
| Optional own-request status without a concrete live path | Own HR-case and active-incident lists | Re-expressed; no inference from the knowledge index |
| Broad HRIS knowledge, including SuccessFactors | Workday is live own-record access, not an HR-policy crawler | Changed to requested focus |
| Default no personal salary answer / no HR writes | No salary lookup; optional existing home-phone update and standard time-off submission | Deliberate scoped expansion; all live skills OFF by default |
| Case data excluded in source prompt examples | Optional own-case tools, never cases as searchable knowledge | Deliberate expansion |
| Legacy seat thresholds, language and channel assumptions | Tenant-specific host, licensing, language and channel validation | Not inherited as product guarantees |

## Included and not included

Included: five scenario documents, provenance and reference links, configuration guidance and references for integrating ServiceNow and Workday with Microsoft Entra ID and configuring the ServiceNow Microsoft 365 Copilot (Graph) connector, an [example source/integration and use-case planning workbook](0.Resources/Use-case-planning.xlsx), a seven-row capability matrix, integration binding requirements, seven individually uploadable runtime skills, and positive/boundary/composed acceptance cases. The workbook is a broader illustrative backlog: defer/not-select rows outside the current matrix.

Not included: execution of tenant-specific configuration changes, connector credentials, backend code, solution exports, deployments, sample personal records, or evidence of live tests. Configuration guidance is included; applying and validating it in the target environment remains the delivery team's responsibility. The [runbook gates](4.Runbook.md#release-gates) assign ownership for these gaps. Supplied tool names/paths remain unverified tenant bindings; home-contact, HR-case and absence data require explicit privacy review.
