# Employee Self-Service Agent with Microsoft Copilot Harness - Overview

> **Scenario Type**: Employee Experience (HR + IT self-service)  
> **Agent Type**: Microsoft Copilot Studio agent, Microsoft Copilot Harness  
> **Primary Tools**: SharePoint and ServiceNow knowledge; proposed delegated ServiceNow and Workday tools  
> **Status**: Authoring blueprint and 28 runtime skill definitions; integrations not implemented or deployed.  
> **Source**: [Employee-Self-Service-Agent](../Employee-Self-Service-Agent/1.Overview.md), local revision `a776697d6c072ec6d4cf8b09ba7670bd11a3e73c`.  
> **Authored**: 2026-10-28. The original scenario remains unchanged.

## Scenario overview

Give employees one authenticated HR and IT front door: answer policy and troubleshooting questions from approved **SharePoint and ServiceNow knowledge**, then, when separately enabled, work with the employee's own **ServiceNow HR cases, ServiceNow IT incidents and Workday information**.

This is a standalone sibling design. The source describes several build options, not a delivered topic-based agent. This variant expresses employee HR and IT capabilities as focused skills and narrow backend contracts for the **Microsoft Copilot Harness inside Copilot Studio**, not Copilot CLI or GitHub coding agents.

**Implementation boundary:** This repository supplies the procedures and contracts, **not executable connectors, MCP servers or workflows**. Uploading skills does not create integrations or grant access. Live capabilities stay OFF until a supported Microsoft Copilot Harness integration is delivered and validated.

## Users and outcomes

| Persona | Need | Measurable outcome |
|---|---|---|
| Employee | Find the applicable HR policy or IT fix without portal hopping | Time to a correct cited answer, compared with a pre-pilot baseline |
| Employee with enabled transactions | Read own requests and HR information; make a specifically confirmed change | Authorized read accuracy and verified completion; no cross-user disclosure or duplicate writes |
| HR Operations | Consistent guidance and safe case intake | Deflection for the top 25 question categories; source-owner review of failures |
| IT service desk | Useful incident descriptions and transparent status | Confirmed incident creation, description fidelity and fewer status-chasing contacts |
| Delivery, identity and system owners | Independently enable capabilities without widening access | Signed capability manifest and positive/negative authorization evidence |

These are measures to collect, not achieved results. Establish baselines before the pilot.

## Capabilities and scope

| Capability | Evidence / system | Boundary |
|---|---|---|
| Policy and IT answers | Approved SharePoint libraries and ServiceNow KB articles | Source-grounded, cited, country/effective-date aware; no personal entitlement calculation |
| Request navigation | Approved links retrieved from those sources | Link only; navigation does not submit a request or order a catalog item |
| ServiceNow HRSD | Live delegated tools for create, list, details, latest updates, update and attachments | Own cases only; separate capability and backend authorization for each operation |
| ServiceNow ITSM | Live delegated tools for the same six operations | Incidents, not catalog orders, request fulfillment or change management |
| Workday reads | Separate live tools for 12 employee-information capabilities | Employee's own information only; sensitive fields minimized and separately approved |
| Workday writes | Email and phone update tools | Exact contact record/type and payload, trusted confirmation, concurrency checks and completion verification |

The [matrix](0.Resources/Capability-matrix.md) lists all 28 skills, dependencies and states. The baseline enables only knowledge answers and navigation **after** source validation. Every transactional skill is optional and OFF initially; a knowledge-only pilot must be labeled as reduced scope, not a full implementation.

**Excluded:** SAP SuccessFactors; time-off submission or balances; payroll calculations and payslips; benefits enrollment; compensation changes; editing national IDs, passports, visas or emergency contacts; manager/on-behalf-of access; bulk export; employee profiling; autonomous triggers; mail sending; provisioning; catalog checkout; legal, tax or medical advice. Grievances, termination, discrimination and compensation disputes receive only an approved human contact route; do not collect their narrative into ordinary tickets.

## Compatibility and deliberate changes

| Source behavior | Microsoft Copilot Harness behavior | Disposition |
|---|---|---|
| HR + IT front door, curated content, representative pilot | Same business purpose with SharePoint and ServiceNow KB knowledge | Retained |
| Multiple build options | One new Microsoft Copilot Harness agent; source choices remain useful | Standalone implementation |
| Portal links for requests | Navigation remains available independently of writes | Retained |
| Optional own-request status without a concrete live path | Explicit live list/details/updates contracts | Re-expressed; no inference from the knowledge index |
| Broad HRIS knowledge, including SuccessFactors | Workday is live own-record access, not an HR-policy crawler | Changed to requested focus |
| Default no personal salary answer / no HR writes | Optional own base-compensation read and email/phone updates | Deliberate expansion; sensitive reads and all writes OFF by default |
| Case data excluded in source prompt examples | Optional own-case tools, never cases as searchable knowledge | Deliberate expansion |
| Legacy seat thresholds, language and channel assumptions | Tenant-specific host, licensing, language and channel validation | Not inherited as product guarantees |

## Included and not included

Included: five scenario documents, provenance and reference links, configuration guidance and references for integrating ServiceNow and Workday with Microsoft Entra ID and configuring the ServiceNow Microsoft 365 Copilot (Graph) connector, an [example source/integration and use-case planning workbook](0.Resources/Use-case-planning.xlsx), a complete source/capability matrix, proposed typed integration contracts, 28 individually uploadable runtime skills, and positive/boundary/composed acceptance cases.

Not included: execution of tenant-specific configuration changes, connector credentials, backend code, solution exports, deployments, screenshots, sample personal records, or evidence of live tests. Configuration guidance is included; applying and validating it in the target environment remains the delivery team's responsibility. The [runbook gates](4.Runbook.md#release-gates) assign ownership for these gaps. National-ID, passport, visa, emergency-contact and compensation reads require explicit HR/privacy approval in addition to normal integration checks.
