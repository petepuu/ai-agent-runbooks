# HR Onboarding Agent (GHCP)

## Scenario Overview

| Attribute | Value |
|---|---|
| Scenario type | Employee self-service (HR) |
| Platform | Microsoft Copilot Studio - GitHub Copilot harness |
| Primary components | Instructions, ServiceNow knowledge, reusable Agent Skills, connector tools |
| Complexity | Intermediate; production email automation requires additional controls |
| Status | Implementation guide; target-tenant validation required |
| Documentation reviewed | September 15, 2026 |

This is a separate adaptation of [HR Onboarding Agent](../HR-Onboarding-Agent/1.Overview.md). It preserves the original onboarding questions, ServiceNow knowledge, sample documents, and intended Teams, Microsoft 365 Copilot, and email experiences. It replaces standard-harness authoring guidance with the GitHub Copilot harness approach.

**GHCP here means the harness inside Copilot Studio**, not GitHub Copilot coding agent, a GitHub Actions workflow, or a repository configured with Copilot instructions. Keeping these files in GitHub does not deploy an agent or install its skills.

Microsoft documents that agents cannot be transferred between standard and GitHub Copilot harnesses. Create a new GHCP agent, reuse the knowledge and integration design, and configure its components afresh. Keep the original agent available during the pilot.

## Problem and Outcomes

New hires need reliable answers about onboarding, company policies, benefits, and where to get help. The agent reduces repetitive HR inquiries by retrieving approved policy information, citing its sources, and turning documented onboarding steps into a useful checklist.

The intended outcomes remain faster onboarding, more consistent guidance, and lower HR support workload. Grounding and skills help improve consistency; neither guarantees factual accuracy or eliminates hallucinations.

## Standard vs GitHub Copilot Harness

| Area | Original / standard harness | GHCP implementation in this scenario |
|---|---|---|
| Authoring | Original runbook uses Overview, knowledge, tools, triggers, and one instruction block; standard agents can also use topics and branching | Build brings instructions, knowledge, tools, skills, model, and memory together |
| Orchestration | Standard supports configurable orchestration, including generative orchestration; it is not exclusively scripted | Enhanced orchestration interprets the goal and chooses resources; do not look for the original orchestration-mode switch |
| Reusable behavior | HR answering and email handling live in the main instructions; topics/flows can encode deterministic steps | Three Markdown Agent Skills package HR answering, checklist creation, and email drafting |
| Skills terminology | Older Bot Framework skills, topics, and flows are not these portable skill packages | `SKILL.md` with YAML metadata and Markdown instructions; optional supporting files in a ZIP |
| Knowledge | ServiceNow articles indexed through a Microsoft Copilot Connector | Reconnect approved knowledge in Build; a skill is not a replacement for the connector or its permissions |
| Tools | Outlook `SendEmail` action | Configure actual connector tools separately; a skill describes how to use available capabilities but grants no permissions |
| Email | Original demonstrates automatic replies using maker connections | Rebuild and validate event handling; start draft-only and enable sending only behind recipient, authorization, approval, and duplicate-send controls |
| Determinism | Explicit topics/flows can enforce paths | Skills guide a model; enforce consequential decisions and exact-once protections in tools/workflows, not Markdown alone |
| Memory | Original has no persistent-memory design | Leave memory off for this baseline; HR records and case state do not belong in agent memory |
| Files | Original answers in chat/email | Optional cited onboarding document using native file capabilities; checklist output works without file generation |
| Testing | Original Test panel and Activity tab | Preview, Evaluate, and Monitor; test skill selection and tool effects as well as answer quality |
| Cost | Original licensing/environment assumptions | Verify GHCP Copilot Credits, tenant eligibility, channel licensing, and build/test/evaluation consumption |
| Migration | Existing standard agent remains supported | Side-by-side rebuild, not an import or automatic conversion |

## Skills Included

| Skill | When it should activate | Result |
|---|---|---|
| [hr-policy-answer](./0.Resources/Skills/hr-policy-answer/SKILL.md) | A direct question about a documented HR policy, benefits, leave, payroll process, or onboarding guidance | Supported answer, source links, missing information, and next step |
| [hr-onboarding-checklist](./0.Resources/Skills/hr-onboarding-checklist/SKILL.md) | A first-day/first-week checklist or onboarding plan request | Checklist separating policy requirements from explicitly labeled suggestions |
| [hr-email-triage](./0.Resources/Skills/hr-email-triage/SKILL.md) | A request to draft an HR email response, or an authorized email-event task | Grounded reply proposal or escalation; never an autonomous send by the skill |

The runtime uses skill descriptions to decide which instructions to load. These are not exact trigger phrases or a guaranteed sequential pipeline. The email and checklist skills contain their own grounding requirements, so they do not depend on another skill being invoked first.

## Scope and Safety Defaults

The baseline covers read-only HR Q&A, source-linked checklists, and email reply drafting. Interactive access uses the authenticated user's access boundary. Autonomous work uses its configured connection identity, not automatically the email sender's identity.

Email sending is a separately gated extension of the original scenario, not a capability silently enabled by importing a skill. Personal employee records, medical details, payroll changes, benefit enrollment, account provisioning, live leave balances, and case creation remain out of scope.

The sample knowledge remains the **Contoso Employee Handbook** and **Wellness Benefits Sample Knowledge** documents in [Sample-documents](./0.Resources/Sample-documents/). Treat them as synthetic demonstration content, not current employer policy. The copied `Images` directory preserves the original assets; its screenshots are historical standard-harness/ServiceNow illustrations, not screenshots of the GHCP Build surface.
