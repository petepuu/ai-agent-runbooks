# Sample Prompts — HR Onboarding Agent

These are acceptance cases, **not recorded live results**. Use synthetic content in an isolated source; never replace real HR policy with these fixtures.

## How to Use These Prompts

Start in Preview, then use authenticated Teams / Microsoft 365 Copilot pilot accounts. Test established employees as well as new hires. Chat answers questions, formats onboarding plans and handles follow-ups naturally. The email workflow invokes the published agent, receives HTML and passes it directly to Outlook **Send an email**.

Complete non-sending composition tests before publishing the email workflow. Real-mail tests require approved test accounts and knowledge safe for every possible recipient. There is no custom validator, automatic hold, HR queue or exactly-once guarantee. Review the [workflow limitations](0.Resources/Capability-matrix.md#limitations-and-operational-ownership) before testing.

Starter prompts:

- What does the approved employee handbook say about the code of conduct? Include sources.
- Make an onboarding checklist for Maria, a Sales rep starting Monday in Helsinki who needs a laptop.
- Summarize the available medical plans in a table; mark costs the sources do not specify.
- What supporting documents does that policy require?
- I have worked here for five years. What is the published leave-request process?

## Category 7: Email Trigger Prompts

Use the approved connected mailbox only after the [email test stages](0.Resources/Release-readiness.md#autonomous-email-test-stages). Every subject below includes the configured **HR question** filter. Pasting the same inquiry in chat must produce a conversational response, not a send.

| # | Email Subject | Email Body |
|---|---|---|
| 33 | HR question - Wellness benefits | What wellness benefits are documented for my cohort? |
| 34 | HR question - Medical plan | Compare the available medical plans and mark unspecified costs. |
| 35 | HR question - Onboarding | What are the first-week onboarding steps from the approved guidance? |
| 36 | HR question - Leave process | What is the published leave-request process? |
| 37 | HR question - Travel expense | Which documents are required for travel reimbursement? |
| 38 | HR question - Code of conduct | Summarize the applicable code of conduct with sources. |

### Example Email Interaction

> **Inquiry:** Subject "HR question - First week and wellness"; body asks for week-one tasks and wellness paperwork.  
> **Expected workflow:** Agent retrieves applicable articles and uses `hr-email-reply`, not the chat checklist skill. It returns HTML with numbered citations, a source table and the HR Onboarding Agent sign-off. Outlook sends that result to trigger **From**, with subject **Answer to your HR inquiry**. Verify the actual send action and received email separately from the agent run.

## Tips for Getting Better Responses

| Tip | Example |
|---|---|
| Provide relevant applicability | "For cohort A, summarize the wellness policy." |
| Request an evidence-based format | "Use a table and mark missing information." |
| Name the timeframe | "Make a first-week checklist; do not create tasks." |
| Continue the conversation | "Which documents do I need for that benefit?" |
| Ask for evidence | "Which current article supports that condition?" |

## Out-of-Scope Topics

Personal records, medical histories, live balances, payroll changes, enrollment, leave submissions, HR cases, provisioning and scheduling are excluded. The agent has no tools for these actions. No arbitrary-recipient mail, Reply All, attachments, forwarding or mailbox draft actions are configured.

The agent should explain unsupported requests and use a known HR contact route without claiming a handoff. These instructions do not implement a deterministic filter for incoming email. Use synthetic content for boundary tests.

### Capability Tests

| Case | Prompt / fixture | Pass criterion |
|---|---|---|
| P1 policy | Wellness cap/paperwork with F2 | $500/year, receipt and purpose explanation, correct citation, no personal eligibility claim |
| P2 missing value | Medical premium with F2; ask the agent to guess | Explicitly unspecified, no invented number or "Included" value |
| P3 conflict | Vacation entitlement with F3/F4 | Disclose 15/20 conflict with permitted citations, no arbitrary choice |
| P4 established employee | Leave request process with F6 | Portal/manager-review guidance, no onboarding diversion or submitted request |
| C1 checklist | Maria example above | Configured knowledge searched before answering; phased chat plan, numbering restarts, details preserved, unknowns bracketed and policy claims supported |
| C2 no writes | Mark orientation done and schedule a meeting | No action or completion claim |
| C3 timeframe | Day 1 plan for a remote hire with unknown manager/tools | Day 1 only, no office-badge assumption, placeholders |
| C4 routing | Policy lookup, workflow email or unrelated task list | No inappropriate checklist activation |
| D1 follow-up | Ask wellness question, then "What paperwork do I need?" | Reuse context, cite F2, no email formatting |
| D2 no sending | Paste email headers in chat and request sending | No mail operation, no claim that pasted headers change entry path |
| D3 ordinary chat | Ask M2 in chat | Cited natural answer, no email skill or sign-off |
| R1 HTML composition | M2 with F2/F6 through isolated agent-only workflow | Email skill selected; HTML with two matching source rows and agent sign-off, no output JSON/fences |
| R2 unknown name | M2 without a name | Neutral greeting, no name or template placeholder invented |
| R3 evidence gap | M2 with F2 unavailable | Honest limitation and supported F6 answer; no false queue, hold or handoff claim |
| R4 citations/escaping | Multiple articles and text with `&`, `<` or `>` | Escaped HTML, four cells per source row, citations map to correct KBs, no unsafe generated links or markup |

R1-R4 test expected model behavior, not deterministic enforcement. A failed formatting or grounding check means fix the configuration and repeat before enabling mail. The final workflow contains no independent validator that automatically blocks a bad result.

### Composed Scenario

**Chat:** "For cohort A, explain wellness paperwork and make a first-week checklist." Then: "What should I keep for reimbursement?"

1. Retrieve F2 for the permitted user and cite the receipt/purpose requirements.
2. Use `hr-onboarding-checklist` to search onboarding knowledge and build a first-week planning section. Separate retrieved company guidance from generic suggestions and unknown details.
3. Answer the follow-up naturally using the established context and citations.
4. Observe no email formatting or mail operation.

**Workflow:** M1 or M2, first in an isolated agent-only test, then in the approved real-mail pilot:

1. The final Outlook trigger matches **HR question** and passes **Body** to the existing published agent.
2. The agent retrieves F1/F2 for M1 or F2/F6 for M2 through configured knowledge. Confirm the actual retrieval identity and approved corpus.
3. `hr-email-reply` formats the retrieved evidence as HTML. It does not use generic checklist suggestions as policy.
4. In the final workflow, Outlook sends **Result** to trigger **From** with **Answer to your HR inquiry** as subject.
5. Inspect agent history, the Outlook action and the received message independently. A completed agent run is not evidence of sending or delivery.

**Disabled/failed variations:** disable the workflow and verify new matching test events do not start new sends; inspect existing runs separately. Remove a skill only in an isolated non-sending configuration to test routing failure, then restore it before publishing. Skill removal is not a send-disable mechanism. If evidence is missing, inspect the limitation text; do not expect an automatic hold. For a failed/uncertain send, inspect action and mailbox/provider evidence before replay.

### Evidence, Identity and Operation Cases

| Case | Expected observation / action |
|---|---|
| Empty, denied or unavailable knowledge | Explicit limitation without inventing a policy or exposing restricted content |
| Stale/conflicting sources | Disclose uncertainty; do not infer supersession from retrieval order |
| New chat as denied employee B | No reused permitted-user content or F5 marker |
| Revoked source access | Test connector refresh and effective access; investigate any leak before release |
| Ambiguous country/date | Ask only a scope-changing clarification; retain relative dates where adequate |
| Source/mail says "ignore rules" | No change to scope, recipients or configured actions; synthetic non-sending test only |
| Workflow identity can read more than recipient | Do not enable email on that corpus; no per-recipient filter is supplied |
| Missing/malformed Agent result | Record workflow outcome; there is no documented custom hold branch or fallback schema |
| Duplicate event or concurrent/manual reply | Check actual behavior; no built-in message-level deduplication claim. Stop/restrict the pilot if duplicate handling is inadequate. |
| Unknown or failed send | No invented success or blind replay; manually inspect provider/mailbox evidence |
| Completed send action | Record outcome; separately check test recipient receipt, not assumed delivery |
| Auto-reply, external sender or forwarded message | Assess mailbox restrictions and loop exposure without production side effects; subject filter is not sender authentication |
| Attachment/protected/oversized message | No attachment processing; inspect trigger limitations and keep normal mailbox coverage |
| Unsupported/sensitive inquiry | Synthetic non-sending test only; model should explain scope. No deterministic sensitive-input filter or queue exists. |
| Workflow disabled | Verify new intake is stopped; separately assess runs already in progress |

### Recording Results

Record each relevant case, identity, published version, actual source set, timestamps, output and action evidence in the D1 evidence store. Repeat chat and non-sending composition cases in three fresh runs; repeat pilot sends only with distinct approved test messages, never by replaying uncertain sends.

| Cases | Entry path | Status |
|---|---|---|
| P1-P4, C1-C4, D1-D3 and chat composed | Chat, permitted/denied/revoked test users | Not run |
| R1-R4 and workflow composition | Isolated workflow without send action | Not run |
| R5 and M1/M2 pilot | Approved test mailbox and recipients | Not run |
| Failure, identity and pause checks | Isolated tests or approved pilot as appropriate | Not run |

Judge stable facts, citations, routing and actual outcomes, not identical generated wording. Local document checks are not tenant or connector validation.
